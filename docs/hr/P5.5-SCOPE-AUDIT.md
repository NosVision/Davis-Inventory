# P5.5 Scope-Enforcement Audit — Davis-Inventory HR Module

**Scope:** all 115 route files under `src/app/api/hr/**/route.ts`
**Auth helpers:** `src/lib/hr/route-auth.ts` — `requireHrManager()` (global `can_manage_hr()`), `requireStoreManager(storeId)` (mirrors SQL `can_manage_store()`: company-wide HR **or** a row in `hr_manager_scopes` for that store).
**Scoping fabric:** employees ↔ stores via `user_stores(user_id, store_id)`; HR managers ↔ stores via `hr_manager_scopes(user_id, store_id)`. Most store/employee tables also carry a direct `store_id` (attendance, warnings, offboarding, SC/tip pools, payruns, schedule) or reach one via the employee's `user_stores`.
**Status:** DOCUMENTATION ONLY — no code changed. P5.5 is marked **ห้ามข้าม** (must-not-skip) in `docs/hr/HR-BUILD-STATE.md`. Produced Round 44 (dev DOWN, offline audit).

## Summary

| Classification | Count |
|---|---|
| OK-global (legitimate company-wide config/oversight) | 31 |
| OK-scoped (already `requireStoreManager` or self-scoped ESS) | 51 |
| **NEEDS-SCOPE** (HR-global today, touches store/employee data) | 33 |
| **Total** | **115** |

The core gap: `requireHrManager()` grants any `can_manage_hr` holder global reach. Under the multi-HR model P5.5 introduces, a manager scoped to store A (via `hr_manager_scopes`) must not read/mutate store B's operational rows. Every NEEDS-SCOPE route below must move from `requireHrManager()` to `requireStoreManager(storeId)` (deriving `storeId` from the request or the target row), or add an explicit `user_stores`/`store_id` filter for list endpoints.

## P5.5 Work Checklist (ordered — highest blast radius first)

Each fix: derive `store_id` from the request or target row, then replace `requireHrManager()` with `requireStoreManager(storeId)` (which already lets company-wide HR through), or add a `user_stores`/`store_id` filter for list endpoints. For no-`store_id` tables (assets, documents, eval results) resolve the store via the employee's `user_stores`.

**Tier 1 — payroll & money (highest risk):**
payruns/route · payruns/[id] · finalize · reopen · bank-file · payslips/[id] (isHr branch) · service-charge/route · sc allocations · sc finalize · sc recompute · sc allocations-deductions · sc deductions/[id] · tip-pool/route · tip allocations · tip finalize · tip allocations-deductions · tip deductions/[id]  **(17)**

**Tier 2 — employee master & lifecycle:**
employees/route · employees/[id] · transfer · tax-allowances · recurring · offboarding/route · offboarding/[id] · sign · cancel · complete · documents  **(11)**

**Tier 3 — attendance / time / roster:**
attendance/route · timesheet/override · schedule/acknowledge · dayoff-swaps/[id]/ack · warnings/[id]/void  **(5)**

**Tier 4 — eval, assets, config, ack lists:**
eval assignments · eval results · eval payouts · eval reopen-assignment · assets/route · assets/[id] · locations/route · announcements/[id]/receipts (low) · policies/[id]/acks (low)

**Verification requirement (per fix):** each change needs a **live-auth e2e** with two accounts — (a) an HR manager scoped to store A only (`hr_manager_scopes` row for A, no global `can_manage_hr`) and (b) data belonging to store B. Assert: scoped manager sees/mutates **only** store A rows and gets **403** on store B ids/params; company-wide HR still sees everything. This requires the running dev server (`npm run dev`, and `rm -rf .next` if stale) — it **cannot** be verified by typecheck/build alone. Blocked until the dev server is up.
