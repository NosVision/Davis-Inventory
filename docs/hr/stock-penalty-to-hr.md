# สเปก: ระบบหักคะแนน/ค่าปรับนับสต๊อก → เชื่อม HR (SV + ใบเตือน)

> สรุปกฎจากเจ้าของร้าน (2026-07-09) + ออกแบบการทำงาน/ข้อมูล/หน้าจอ เพื่อพัฒนาต่อ
> ร้านอ้างอิง: BACCARAT — ต่อยอดจาก [payroll-real-formula-analysis.md](payroll-real-formula-analysis.md)

---

## 1. หลักการ: "2 นาฬิกา แยกกัน"

การ **นับแต้ม (วินัย)** กับ การ **หักเงิน** เดินคนละจังหวะ — ห้ามผูกเป็นตัวเดียวกัน

| | 🕐 นาฬิกาเงิน (หัก SV) | 🗓️ นาฬิกาวินัย (SOP → ใบเตือน) |
|---|---|---|
| นับอะไร | เฉพาะครั้งที่ "หักเงินจริง" | **ทุกความผิด** (รวมครั้งที่ยังไม่หัก) |
| หน้าต่างเวลา | **รายสัปดาห์ (จ–อา)** รีเซ็ตทุกวันจันทร์ | **เดือนปฏิทิน** รีเซ็ตทุกวันที่ 1 |
| ผลลัพธ์ | หักจากกอง SV ของคนที่รับผิด | ครบ **7 แต้ม → ใบเตือนหัวหน้าบาร์ 1 ใบ** |
| ลงเงินจริงเมื่อ | ตาม **รอบเงินเดือน 26–25** | — (ไม่เกี่ยวเงิน) |

## 3. ใครรับผิด (attribution)

- **เป็นความรับผิดร่วมของกะ** — หัก**คนละ** (ไม่ใช่หารกัน) กับ **บาร์ทุกคนที่เข้ากะในวันที่ถูกตรวจ**
- การนับสต๊อกทำก่อน 05:00 ของเช้า → ตรวจยอดของ **"วันธุรกิจก่อนหน้า"** ดังนั้น:
  - นับผิดวัน**พุธ** → หักบาร์ที่เข้ากะวัน**อังคาร**
  - นับผิดวัน**ศุกร์** → หักบาร์ที่เข้ากะวัน**พฤหัส**
- ⟹ **ผู้รับผิด = พนักงานบาร์ (role `bar` / `head_bar`) ที่มีกะทำงานในวันธุรกิจที่ถูกตรวจ** — ดึงจากตารางกะ/เช็คอิน HR (`hr_schedule` / `hr_attendance`)
- แทบไม่มีการชี้ตัวคนเดียว (แต่ระบบยังเปิดให้ owner/HQ ระบุ `responsible_staff_id` รายคนได้เหมือนเดิม ถ้าต้องการ)

---

## 4. การหักเงิน (ฝั่ง HR / SV)

- หัก**จากกอง Service Charge เท่านั้น** — เงินเดือนฐานไม่แตะ (ยกเว้น "มาสาย" ซึ่งเป็นระบบเดิม อยู่นอกสเปกนี้)
- **ลงเงินจริงตามรอบเงินเดือน 26–25** (ไม่ใช่ปฏิทิน)
- ถ้ากอง SV ของคนนั้นในรอบนั้น **ไม่พอ/เป็น 0 (เช่น มิ.ย.) → ยกยอดไปหักรอบถัดไป** (carry) — ห้ามไปหักเงินเดือน
- ต้องมี **tracking สถานะต่อรายการ:** `รอหัก → หักแล้ว(บางส่วน) → ยกยอด → หักครบ`
- ใช้โครงสร้างเดิม `hr_sc_deductions` (มี `carry_satang` อยู่แล้ว) → เพิ่ม `source_type = 'stock_penalty'`
- **กันหักซ้ำ:** 1 เหตุการณ์ หักที่ SV ที่เดียว — ไม่มีทาง double กับเงินเดือน

**การหักมี 2 แบบ:**
- **แบบ A — SOP (มีโครงสร้าง):** เฉพาะ **bar + head_bar** → เข้าเครื่อง escalate / นับ SOP / → ใบเตือน (ทั้งหมดในสเปกนี้)
- **แบบ B — Ad-hoc (นอก SOP):** **HQ หักใครก็ได้** (staff / manager / cashier / …) แบบ **"เหตุผล + จำนวนเงิน"** เฉยๆ — ไม่มีรหัส ไม่ escalate ไม่นับ SOP · หักเข้า SV เหมือนกัน · เป็นเคสนานๆที (ใช้ `hr_sc_deductions` source_type `'manual'` เดิม)

---

## 5. ใบเตือน (วินัย → HR)

- SOP แต้มสะสม**ต่อร้าน ต่อเดือนปฏิทิน** — ครบ **7** → ระบบเตือน HQ + สร้าง/เตรียมใบเตือน (`hr_warnings`) ให้ **หัวหน้าบาร์ของร้านนั้น (role `head_bar`)** 1 ใบ
- **การส่งต่อไป HR: ตั้งรวมทั้งระบบ (global switch)** — เจ้าของเคาะ:
  - **Auto** — ครบ 7 ระบบส่งเข้าคิว HR ออกใบเตือนเอง
  - **Manual** — HQ เป็นคนกดส่งเอง (ธง `escalated_to_hr_at` เดิม)
- ใบเตือนเข้ากระบวนการเดิม (เซ็น 3 ฝ่าย + หมดอายุ 12 เดือน)
- ปลายทาง = **role `head_bar` ของร้านนั้น** (เจ้าของจะตั้งให้แต่ละร้านเอง) — ถ้ายังไม่ตั้ง → default = เจ้าของร้าน + เตือนให้ตั้ง

---

## 6. สิ่งที่ต้องแก้ในระบบเดิม

1. **แยก "นับแต้ม" ออกจาก "หักเงิน"** — 1 เหตุการณ์สร้าง (ก) SOP point เสมอ (ข) SV deduction เฉพาะเมื่อเข้าเงื่อนไขเงิน
2. **ตัวนับ SOP เปลี่ยนจากรายคน → รายร้าน** (ตอนนี้ owner-review นับ `per staff_id`; เกณฑ์ 7 ต้องเป็นของทั้งร้าน)
3. **เพิ่ม engine escalate รายสัปดาห์ของ A-02** (นับครั้งที่ 1/2/3 ของร้านในสัปดาห์ จ–อา → 0/300/500)
4. **ต่อ `penalties`/violation → `hr_sc_deductions` (SV) + carry** และ **→ `hr_warnings`** เมื่อครบ 7
5. **ดึง "คนเข้ากะวันธุรกิจที่ตรวจ" จาก HR** เพื่อกระจายค่าปรับ

## 7. หน้าจอที่ต้องมี (3 ฝั่ง)

### 7.1 หน้าจัดการสำหรับ HQ (ใหม่)
- สรุป **รายสัปดาห์** (ครั้งที่ 1/2/3 ของแต่ละร้าน + ใครโดนหักเท่าไร) และ **สะสมรายเดือน** (แต้ม SOP ต่อร้าน, ใกล้ 7 แค่ไหน)
- รายการค่าปรับ + สถานะการหัก SV
- **สร้างหักแบบ Ad-hoc (แบบ B):** ระบุคน + เหตุผล + จำนวนเงิน → หัก SV (ใครก็ได้: staff/manager/cashier/…)
- **จัดการประกาศ SOP:** publish/แก้เวอร์ชัน ให้ bar/head_bar กดยอมรับ (ดู 7.4)
- สวิตช์ **ส่ง HR Auto ↔ Manual** (ตั้งรวมทั้งระบบ)
- สิทธิ์เข้า: role `hq` (+ owner)

### 7.2 ฝั่ง HR
- คิว "แจ้งหักเงินเข้ามา" จากสต๊อก → เลือก **หักรอบนี้ / ยกยอดรอบหน้า** (ค่าเริ่มต้น: หักเท่าที่ SV มี, ที่เหลือ carry อัตโนมัติ)
- **Tracking**: ยอดค้าง/ยกยอด/หักครบ ต่อคน ต่อรอบ
- คิวใบเตือน (จากเกณฑ์ 7) → ออกใบเตือน head_bar

### 7.3 ฝั่งพนักงาน (เมนู "ของฉัน" /me)
- การ์ดใหม่: **"คะแนน/ค่าปรับสต๊อก"** — เห็นของตัวเอง: แต้ม SOP เดือนนี้, ค่าปรับที่โดน, สถานะ (รอหัก/หักแล้ว/ยกยอด), ประวัติย้อนหลัง
- ใช้แถบแจ้งเตือนแบบเดียวกับที่ทำไว้ (TileNotices)

### 7.4 ประกาศ & ยอมรับ SOP (เหมือนระเบียบบริษัท)
- ใช้ระบบ **`hr_policies` + ยอมรับต่อเวอร์ชัน** เดิม (ตัวเดียวกับระเบียบบริษัท: เลื่อนอ่านสุด → กดยอมรับ → เก็บตามเวอร์ชัน)
- **HQ เป็นคนจัดการ** (publish / แก้เวอร์ชัน) — เพิ่มสิทธิ์จัดการ policy ให้ role `hq` (เดิม owner/HR)
- **Version 1 = เนื้อหา SOP จากลิงก์ไฟล์ที่เจ้าของส่ง** (ระเบียบปฏิบัติงานฯ บาร์)
- Scope = **bar + head_bar** · เด้งให้กดอ่าน/ยอมรับ **หลังผูกบัญชีแล้วเท่านั้น**
- อัปเดตเวอร์ชันใหม่ → แจ้งเตือน + ต้องยอมรับใหม่

## 8. โครงข้อมูล (เสนอ)

- **ต่อยอด `penalties` เดิม** (มี `staff_id, amount, penalty_code, comparison_id, month_year, included_in_quota`) — เพิ่มคอลัมน์:
  - `business_date` (วันธุรกิจที่ถูกตรวจ), `week_key` (ปี-สัปดาห์ จ–อา), `week_seq` (ครั้งที่ 1/2/3 ของสัปดาห์), `is_money` (bool — จ่ายเงินไหม), `sc_deduction_id` (FK ไป hr_sc_deductions)
- **SV**: `hr_sc_deductions` + `source_type='stock_penalty'`, `source_ref=penalties.id`, ใช้ `carry_satang` เดิม
- **นับรายร้าน**: view/ฟังก์ชันใหม่ `v_store_monthly_sop_count (store_id, month, points)` (แทน/คู่กับ `v_monthly_violation_count` รายคนเดิม)
- **ตั้งค่า**: `hr_policy_settings` (หรือ `store_settings`) — คีย์: `stock_fine_tiers` [0,300,500], `stock_warning_threshold` 7, `stock_escalation_auto_hr` (bool), `stock_week_start` (จันทร์)

## 9. ค่าที่ตั้งได้ (ไม่ hardcode)
อัตรา 300/500 · เกณฑ์ 7 · จำนวนวันตรวจ/สัปดาห์ · Auto ↔ Manual ส่ง HR · วันเริ่มสัปดาห์ → เก็บเป็น setting ให้เจ้าของ/HQ ปรับเองได้

## 10. เคาะครบแล้ว ✅ (พร้อมเข้าเฟส 1)
1. **นับ SOP** — ทุกความผิดนับหมด **ยกเว้น EXP-01** → `included_in_quota` เดิมถูกต้อง ไม่ต้องแก้
2. **Auto/Manual ส่ง HR** — **ตั้งรวมทั้งระบบ (global)**
3. **Head Bar** — เจ้าของตั้ง role ให้แต่ละร้านเอง (ถ้ายังไม่ตั้ง → default เจ้าของ)
4. **หัก 2 แบบ** — A (SOP: bar/head_bar) · B (ad-hoc: HQ หักใครก็ได้ ด้วยเหตุผล+จำนวนเงิน)
5. **ประกาศ SOP** — reuse `hr_policies`, HQ จัดการ, v1 จากไฟล์, bar/head_bar กดยอมรับหลังผูกบัญชี

---

## 11. แผนทำเป็นเฟส
1. **DB + engine** — ต่อยอด penalties (คอลัมน์ใหม่), escalate รายสัปดาห์, SOP รายร้าน, hook SV + warning
2. **ฝั่ง HR** — SV deduction + carry tracking, คิวใบเตือน
3. **หน้า HQ** — สรุปสัปดาห์/สะสม + สวิตช์ auto/manual (global) + **หัก ad-hoc (แบบ B)**
4. **ฝั่งพนักงาน** — การ์ด /me + ประวัติ
5. **ประกาศ SOP** — reuse ระบบ policies, HQ publish v1 จากไฟล์, bar/head_bar ยอมรับหลังผูกบัญชี
